# MyVault Flag Server

Rust implementation of the handshake described in
`../app/docs/flag-api.openapi.yaml`.

## Run

```sh
cargo run
```

The server listens on `0.0.0.0:3000` by default. Override with:

```sh
BIND_ADDR=127.0.0.1:8080 cargo run
```

## Flag generation

The plaintext flag is generated per client RSA public key. The server computes:

```text
fingerprint = base64url_no_pad(sha256(publicKey DER SubjectPublicKeyInfo))
```

The default template is:

```text
HZU18{my_vault_$fingerprint}
```

Override the template with `FLAG_TEMPLATE`; both `$fingerprint` and
`{fingerprint}` placeholders are supported.

## App certificate check

The attestation application ID must include package
`mn.haruulzangi.u18_2026.my_vault` and signing certificate SHA-256:

```text
41:03:F8:79:3D:C7:77:61:AF:7F:1F:0D:65:96:43:46:17:35:5F:56:51:7F:94:D3:AB:3D:4A:94:B4:A9:3A:F3
```

Set `UNSAFE_EXPECTED_APP_CERTIFICATE_DIGEST` to a specific SHA-256 digest to
override the expected signing certificate digest. Set it to `*` to bypass only
the signing certificate digest check. The package name check still applies.

## Device safety check

The attestation root of trust must report a locked device, verified boot state
`Verified`, and non-zero verified boot key and hash values.

Set `UNSAFE_DISABLE_DEVICE_SAFETY_CHECKS=1` to bypass these device safety
checks. Other attestation checks still apply.

## API

`POST /api/flag` requires an OkHttp user-agent (`okhttp/<version>`) and accepts:

```json
{
  "clientNonce": "base64-encoded 32-byte nonce",
  "publicKey": "base64-encoded X.509 SubjectPublicKeyInfo RSA public key",
  "attestationCertificates": [
    "base64-encoded DER Android key attestation leaf certificate",
    "base64-encoded DER issuer certificate"
  ]
}
```

The server verifies the Android key attestation certificate chain, confirms the
leaf certificate public key matches `publicKey`, and requires the attestation
challenge to exactly match `clientNonce`. The attested key must be generated by
AndroidKeyStore and authorized for RSA decrypt. Software-backed and
hardware-backed AndroidKeyStore attestations are accepted when they chain to a
trusted Android attestation root.

It returns base64 fields:

```json
{
  "encryptedSessionKey": "RSA-OAEP-SHA256 encrypted AES-256 key",
  "flagIv": "AES-GCM IV",
  "encryptedFlag": "AES-GCM ciphertext with tag appended",
  "aad": "CBOR byte string containing clientNonce"
}
```

For the required 32-byte nonce, `aad` is base64 of `0x58 0x20 || clientNonce`.
